# Doctor Signup with Verification Implementation

## Summary
Doctor signup now requires document upload and admin approval before account activation. Added clinicLocation field to doctor profile.

## Changes Made

### 1. Database Schema Updates (All 3 backends)
- Added `DoctorVerificationStatus` enum (PENDING, APPROVED, REJECTED)
- Added `clinicLocation` field to Doctor model (String, optional)
- Added verification fields to Doctor model:
  - `licenseNumber`: String (optional)
  - `verificationDocument`: String (URL to uploaded file)
  - `verificationStatus`: DoctorVerificationStatus (default: PENDING)
  - `verificationNotes`: String (admin notes)
  - `verifiedAt`: DateTime
  - `verifiedBy`: String (admin ID)
- Changed `isActive` default to `false` (was `true`)
- Updated schema in:
  - fyp-admin/backend/prisma/schema.prisma
  - fyp-doctor/backend/prisma/schema.prisma
  - fyp-patient/backend/prisma/schema.prisma

### 2. Frontend (fyp-doctor)
- Created new signup page with:
  - File upload for verification documents (PDF, JPG, PNG, max 5MB)
  - Form fields: firstName, lastName, email, phone, licenseNumber, specialization, clinicLocation, address, city, password
  - Success screen explaining approval process
  - Validation for file type and size
- Location: `fyp-doctor/frontend/src/app/signup/page.tsx`

### 3. Backend (fyp-doctor)
- Updated auth controller with:
  - Multer configuration for file uploads
  - File validation (type, size)
  - Creates doctor with PENDING status
  - Stores uploaded document in `/uploads/verification-documents/`
  - Login checks for verification status
  - Handles clinicLocation field
- Added multer dependency to package.json
- Updated server to serve uploaded files
- Location: `fyp-doctor/backend/src/controllers/auth.controller.js`

## How It Works

1. **Doctor Signup**:
   - Doctor fills form including clinicLocation and uploads verification document
   - Account created with `verificationStatus: PENDING` and `isActive: false`
   - Success message shown explaining approval process

2. **Admin Review** (To be implemented):
   - Admin views pending applications in admin panel
   - Admin downloads/views verification document
   - Admin approves or rejects with notes
   - On approval: `verificationStatus: APPROVED`, `isActive: true`, `isVerified: true`
   - On rejection: `verificationStatus: REJECTED`

3. **Doctor Login**:
   - If PENDING: "Your account is pending admin approval"
   - If REJECTED: "Your account application was rejected"
   - If APPROVED but inactive: "Your account is inactive"
   - If APPROVED and active: Login successful
