===========================================
HOW IT WORKS
===========================================

AVAILABILITY CHECKING:
----------------------
1. Calling agent requests: GET /api/public/doctors/{id}/availability?date=2024-03-15&time=14:30
2. System checks:
   ✓ Doctor exists and is active
   ✓ Date is not in the past
   ✓ Day is in doctor's working days
   ✓ Time is within working hours
   ✓ No conflicting appointments
   ✓ Date is not in blocked dates list
3. Returns: available: true/false with details

APPOINTMENT BOOKING:
--------------------
1. Calling agent sends: POST /api/public/doctors/{id}/appointments
   Body: { patientName, patientPhone, date, time, ... }
2. System:
   ✓ Verifies doctor availability
   ✓ Finds or creates patient account
   ✓ Creates appointment with status "PENDING"
   ✓ Returns appointment details
3. Appointment immediately appears in doctor's dashboard

FRONTEND DISPLAY:
-----------------
1. Dashboard page shows today's appointments
2. Appointments page shows all appointments
3. Doctors can update status (PENDING → CONFIRMED → COMPLETED)
4. Real-time updates when new appointments are created

===========================================
API ENDPOINTS SUMMARY
===========================================

PUBLIC ENDPOINTS (No Auth Required):
-------------------------------------
GET    /api/public/doctors
       → Get all active doctors

GET    /api/public/doctors/:doctorId/availability?date=X&time=Y
       → Check if specific time is available

GET    /api/public/doctors/:doctorId/slots?date=X
       → Get all available slots for a day

POST   /api/public/doctors/:doctorId/appointments
       → Book an appointment

PROTECTED ENDPOINTS (Auth Required):
-------------------------------------
GET    /api/doctor/availability
       → Get doctor's own availability settings

PUT    /api/doctor/availability
       → Update availability (including blocked dates)

GET    /api/doctor/appointments
       → Get all appointments

PUT    /api/doctor/appointments/:id
       → Update appointment status

EXAMPLE CALLING AGENT FLOW
===========================================

SCENARIO: Patient calls and wants to book appointment

1. AGENT: "Let me check Dr. Smith's availability for March 15th at 2:30 PM"
   
   API CALL:
   GET /api/public/doctors/abc123/availability?date=2024-03-15&time=14:30
   
   RESPONSE: { "available": true }

2. AGENT: "Great! That time is available. Let me book it for you."
   
   API CALL:
   POST /api/public/doctors/abc123/appointments
   {
     "patientName": "Jane Doe",
     "patientPhone": "+1234567890",
     "patientEmail": "jane@example.com",
     "date": "2024-03-15",
     "time": "14:30",
     "reason": "Follow-up consultation"
   }
   
   RESPONSE: { "success": true, "appointment": {...} }

3. AGENT: "Your appointment is confirmed for March 15th at 2:30 PM with Dr. Smith"

4. DOCTOR: Sees the new appointment in their dashboard immediately

===========================================
IMPORTANT NOTES
===========================================

1. PATIENT ACCOUNTS:
   - Automatically created if they don't exist
   - Matched by email or phone number
   - Temporary password set for new accounts

2. APPOINTMENT STATUS:
   - New appointments start as "PENDING"
   - Doctor can change to "CONFIRMED", "COMPLETED", or "CANCELLED"

3. TIME SLOTS:
   - 30-minute intervals by default
   - Customizable duration when booking

4. BLOCKED DATES:
   - Doctors can block specific dates (holidays, vacations)
   - System prevents bookings on blocked dates
   - Managed through availability page

5. REAL-TIME UPDATES:
   - Frontend automatically shows new appointments
   - No manual refresh needed
